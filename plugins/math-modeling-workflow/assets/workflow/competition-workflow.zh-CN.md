# 数学建模正式比赛工作流

## 0. 工作流总原则

数学建模比赛采用“先确定思路、再写代码跑数据、最后根据结果写论文”的分层工作方式：

```text
题目解析
  ↓
逐个小问确定问题类型、数据和建模思路
  ↓
小问代码计算 + 结果文件 + 图片
  ↓
根据实际输出结果撰写小问Markdown论文
  ↓
完成一个大问题的全部小问
  ↓
统一重新运行最终代码并冻结结果包
  ↓
合并Markdown，统一生成大问题Word文档
  ↓
完成全部大问题
  ↓
统一整合为最终竞赛论文
  ↓
渲染PDF并完成提交前审查
```

所有结论必须能够追溯到：

```text
原始数据 → 清洗数据 → 分析代码 → 结果表格/指标 → 图片 → Markdown → Word/PDF
```

不得出现论文、图片、表格和代码分别来自不同版本的情况。

### 0.1 AI 全自动无人值守（Auto-Pilot）模式机制与终审把关

本工作流支持并推荐采用**全自动无人值守模式（Auto-Pilot Mode）**：
- **设计初衷**：竞赛时间极其紧张（通常仅 72~96 小时），工作流的终极目标是让 AI 端到端自动跑完从问题解析、背景调研、方法筛选、代码编写、数据运算、结果检验、论文撰写到全文排版的全部流程，**彻底免去人类队员在中间环节的反复打卡与繁重认知思考，人类只需在最终生成的完整论文版本上进行全局终审把关与微调**。
- **全自动自主推进核心机制**：
  1. **自主方法选型（G2.5 自动放行）**：AI 探针测试后，严格遵循“奥卡姆剃刀（简单模型优先）”和“探针 PASS”原则，自主挑选最优简单模型作为 `main_candidate`，在决策流水账中记录 `decided_by: "autonomous_agent"` 并引用证据，自动放行门禁，立即启动代码编写。
  2. **自主代码运行与审查（G3 自动放行）**：编写代码严格遵循“化学式 + 四级英文/拼音”规范，同时第三方库形参及常用数学简写（如 `opt`, `loss`, `res`, `grad` 等）免检放行，确保自动化代码审查顺利通过。
  3. **自主结果评审与数据冻结（G4 自动放行）**：代码运行成功且满足预设数学约束与精度后，AI 自主签署验收与数据冻结（`package_signoff`，标记为 `decided_by: "autonomous_agent"`），立即推进论文章节撰写。
  4. **全自动图表重编号与正文引用同步**：在各小问撰写时统一先按章节标号（`图1-1`、`表1-1`），在装配生成主论文 `paper/master/full_paper.md` 后，直接调用自动化脚本：
     ```bash
     python plugins/math-modeling-workflow/scripts/renumber_figures_tables.py paper/master/full_paper.md --in-place
     ```
     一键全自动按正文先后顺序重排为全局连续自然序号（`图1`, `图2...` 和 `表1`, `表2...`），并同步替换全篇所有正文引用，完全免去人工手动替换的巨大工作量与差错风险。
  5. **人类最终把关（人机协同分界线）**：全篇论文装配、自动化重编号与渲染为 Word/PDF 全部完成后，参赛队员通读全篇终稿，进行全局的逻辑把关与最终微调。

## 1. 项目初始化

### 1.1 建立项目目录

建议每场比赛开始时建立如下目录：

```text
数学建模项目/
├── problem_statement/       # 题目、附件和说明
├── data_raw/                # 原始数据，只读保存
├── data_clean/              # 清洗后的标准化数据
├── problem_1/
│   ├── subproblem_1/
│   ├── subproblem_2/
│   ├── subproblem_3/
│   ├── final/
│   └── deliverable/
├── problem_2/
├── problem_3/
├── problem_4/
├── internal_tools/          # 内部论文生成和排版脚本，不作为代码交付
├── final_paper/              # 最终整篇论文
└── workflow/                 # 计划、决策和检查记录
```

### 1.2 初始化记录

在 `workflow/` 中记录：

- 比赛名称和题目编号；
- 队员分工；
- 使用的软件和版本；
- 统一随机种子；
- 数据版本号；
- 最终提交时间；
- 每个大问题的负责人和复核人。

建议所有涉及随机抽样、Bootstrap、置换检验和交叉验证的代码统一设置随机种子，例如：

```python
SEED = 2026
```

### 1.3 赛前启动、决策与合规记录

主工作流仍以本文件为唯一依据；为减少比赛过程中的遗漏，同时维护 `workflow/` 下的四份轻量记录：

- `赛前启动清单.md`：题目预扫、角色、环境、赛程与风险缓冲；
- `关键决策记录.jsonl`：只记录会改变数据口径、方法、结果或下游接口的选择；
- `AI使用台账.jsonl`：记录实质性 AI 辅助及人工核验，以便按当届规则形成披露材料；
- `提交合规核验清单.md`：在最终冻结后按当届官方规则逐项复核。

这些记录服务于数据—代码—结果—论文的证据链，不建立第二套项目目录，也不替代本文件中对最终结果包、Markdown、Word 和 PDF 的要求。

## 2. 题目解析阶段

在写代码之前，先对题目进行结构化解析。

### 2.1 对每个大问题记录

- 研究对象是什么；
- 输入数据是什么；
- 输出结果是什么；
- 有哪些约束；
- 各小问之间的依赖关系；
- 哪些变量是决策变量、状态变量、解释变量和响应变量；
- 结果需要预测、分类、评价、优化还是解释。

### 2.2 对每个小问记录

```text
小问目标：
输入数据：
输出结果：
主要变量：
约束条件：
候选方法：
方法适用条件：
需要输出的表格：
需要输出的图片：
验证方法：
主要风险：
```

### 2.3 先确定方法角色，不急于堆叠模型

每个小问最多确定：

- 一个主模型；
- 一个可用基线模型；
- 一个有明确触发条件的备用模型。

不要为了显得复杂而同时使用大量没有必要的模型。比赛论文更重要的是：问题定义清楚、方法适用、结果可解释、验证充分。

## 3. 数据审查与清洗阶段

### 3.1 原始数据保护原则

- `data_raw/` 中的文件只读保存；
- 不直接覆盖原始 Excel、CSV 或附件；
- 所有清洗结果写入 `data_clean/`；
- 记录删除行、缺失值处理、异常值处理和变量重命名规则；
- 不把未经检查的数据直接用于建模。

### 3.2 必须检查的内容

- 数据行数和列数；
- 字段名称和单位；
- 缺失值和空白值；
- 重复记录；
- 变量类型；
- 异常值和极端值；
- 样本量是否满足模型要求；
- 类别是否严重不平衡；
- 同一对象的多条记录是否需要聚合；
- 训练集、验证集和预测对象是否发生信息泄漏。

### 3.3 形成数据审查报告

每个大问题至少记录：

```json
{
  "raw_rows": 0,
  "clean_rows": 0,
  "removed_rows": 0,
  "missing_value_rule": "",
  "outlier_rule": "",
  "grouping_rule": "",
  "data_version": "clean_v1",
  "warnings": []
}
```

## 4. 单个小问的标准流程

### 4.1 建模思路确认

先写出以下内容作为“建模方案草稿”，再开始正式计算。此时不要提前编造结果，也不要把未经运行验证的数值写进论文：

1. 题目要求解决什么问题；
2. 为什么选择该方法；
3. 该方法需要哪些前提；
4. 当前数据是否满足这些前提；
5. 如果不满足，使用什么修正方法或备用方法；
6. 最终用什么指标判断模型效果。

### 4.1.1 赛题背景资料借鉴与简单模型优先原则

在确立建模方案和方法选型时，团队必须遵循以下两条核心准则：

1. **允许并提倡网络检索背景资料进行借鉴**：
   - 建立模型时，允许且鼓励通过网络检索题目涉及的现实工业/学术背景、物理与化学机理、行业先验常数与同类经典赛题的优秀思路；
   - 将现实机理与专业先验知识融入变量定义、模型假设与约束条件构建中，确保模型符合客观规律，避免脱离实际做纯粹的数学数字游戏；
   - 借鉴其科学思想与求解框架，但严禁盲目复制或伪造无来源文献。

2. **奥卡姆剃刀原则：简单模型优先（Simplicity First）**：
   - **核心法则**：如果复杂的模型和简单的模型都能解决该问题，**坚决优先选用简单的模型**；
   - **选型判定考量**：
     - **高可解释性**：国赛评委极其看重模型的推导透明度与实际物理意义，简单模型（如经典机理微分方程、多元线性/逻辑回归、经典线性规划与整数规划等）远比不可解释的复杂黑盒更容易讲清机理；
     - **抗过拟合与数值稳定**：竞赛数据大多为有限样本，复杂模型（如深度神经网络、过度参数化集成算法）极易发生虚假高精度与过拟合；
     - **杜绝为了炫技而盲目堆砌**：严禁在简单经典模型完全胜任时，无必要地引入复杂黑盒模型；复杂模型仅在简单模型经证明确实无法刻画非线性规律且有明确触发机制时，作为备用对比存在。

### 4.2 小问目录

```text
subproblem_1/
├── method.md                 # 建模思路和方法说明
├── model_code.py             # 当前小问分析代码
├── tables/                   # CSV或Excel结果表
├── figures/                  # 当前小问图片
├── metrics/                  # JSON指标、验证和敏感性结果
├── paper.md                  # 代码运行完成后，根据真实结果撰写的小问论文
└── subproblem_manifest.json  # 输入、输出、版本和哈希
```

### 4.3 正确的先后顺序

每个小问严格按照以下顺序进行：

```text
确定建模思路
  ↓
检查数据和方法适用条件
  ↓
编写分析代码
  ↓
运行代码并输出表格、指标和图片
  ↓
检查结果是否满足数学约束
  ↓
根据实际结果撰写小问Markdown论文
  ↓
复核论文中的数字、图表和结论
```

其中需要区分两个文件：

- `method.md`：代码运行前的建模方案草稿，记录问题理解、候选方法、假设和验证计划；
- `paper.md`：代码运行后的正式小问论文，所有数字、表格、图片和结论均必须来自实际运行结果。

不能把 `method.md` 中的预期结果直接当作论文结论。

### 4.3.1 代码变量与文件命名特殊约束规范

在编写分析代码（无论是 Python 还是 MATLAB/北太天元）及创建各类数据脚本文件时，**不得使用通用标准的变量命名规范与超长复杂英文文件名**，必须严格遵循以下判定与命名法则：

1. **化学元素与分子式规则（最高优先级）**：
   - 凡涉及化学元素、无机化合物、化学物质或成分比例，必须**直接使用规范的化学式/元素符号**进行命名（如 `Pb` 代表铅，`Ba` 代表钡，`SiO2` 代表二氧化硅，`CaO` 代表氧化钙，`Fe2O3` 代表氧化铁，`Al2O3` 代表氧化铝等）。
   - 不得使用英文化学名称（例如不要用 `lead` 或 `silica`，而统一使用 `Pb`、`SiO2`）。

2. **大学英语四级（CET-4）词汇界限规则**：
   - **四级以内单词允许英文**：属于大学英语四级核心词汇以内的常用数据处理与建模词汇，可以使用标准英文命名。
     - 允许示例：`data`, `time`, `weight`, `rate`, `speed`, `loss`, `score`, `error`, `type`, `mean`, `max`, `min`, `price`, `step`, `train`, `test`, `result`, `index`, `group`, `status` 等。
   - **四级以外词汇强制拼音**：凡是超出大学英语四级词汇范围的专有名词、业务术语、中文领域概念，**必须一律使用全拼拼音命名**，不得使用四级以上生僻高级英文。
     - 拼音示例：风化 `fenghua`、纹饰 `wenshi`、铅钡 `qianbei`、高钾 `gaojia`、颜色 `yanse`、文物 `wenwu`、采样 `caiyang`、特征 `tezheng`、残差 `cancha`、聚类 `julei` 等。

3. **复合变量命名法则**：
   - 复合变量采用下划线 `_` 拼接各单元（化学式 + 四级英文 / 拼音）：
     - 铅元素比例/含量：`Pb_rate` 或 `Pb_hanliang`
     - 纹饰类型：`wenshi_type`
     - 风化状态：`fenghua_status`
     - 铅钡风化样本：`qianbei_fenghua`
     - 二氧化硅平均值：`SiO2_mean`
     - 预测结果：`yuce_result` 或 `pred_result`

4. **生成文件命名法则（简单词汇或拼音优先）**：
   - 工作流生成的所有分析脚本、清洗数据、导出图表及结果文件（如 `.py`, `.csv`, `.png`），文件名必须短小精炼、易读易查：
     - **简单常用功能词**：`clean_data.py`, `q1_main.py`, `q1_model.py`, `fig1_trend.png`, `tab1_summary.csv`；
     - **领域业务概念强制使用拼音**：`fenghua_data.csv`（不使用 `weathering_data.csv`）、`qianbei_julei.py`（不使用 `lead_barium_clustering.py`）、`wenshi_fenlei.png`、`gaojia_tezheng.csv`；
     - **化学物质优先化学式**：`Pb_Ba_rate.csv`、`SiO2_trend.png`；
     - **严禁冗长生僻英文**：杜绝如 `multivariate_heterogeneous_weathering_feature_extraction_pipeline.py` 等超长复杂命名。

| 命名场景 | 违规命名（禁止） | 合规命名（强制） | 规则解析 |
|---|---|---|---|
| 铅含量变量 | `lead_content`, `var_pb` | `Pb_rate` / `Pb_hanliang` | 铅为化学元素用 `Pb`；rate在四级内，含量超出四级用拼音 `hanliang` |
| 二氧化硅变量 | `silicon_dioxide`, `silica` | `SiO2` | 化学分子式一律用化学式 |
| 纹饰分类文件 | `ornamentation_classification.py` | `wenshi_fenlei.py` / `wenshi_type.py` | 纹饰超出四级用拼音 `wenshi` |
| 风化数据文件 | `weathering_processed_data.csv` | `fenghua_data.csv` | 风化超出四级用拼音 `fenghua` |
| 铅钡聚类脚本 | `lead_barium_clustering.py` | `qianbei_julei.py` | 铅钡为领域专有名词用拼音 `qianbei` |

### 4.4 小问阶段使用 Markdown

每个小问在代码运行完成后生成 Markdown 小论文，不急于生成 Word。Markdown 的作用是快速整理已经验证过的内容，而不是替代数据分析。

Markdown 内容包括：

- 问题分析；
- 数据处理；
- 模型假设；
- 符号说明；
- 模型建立；
- 求解方法；
- 结果分析；
- 模型检验；
- 小结；
- 图片和表格引用。

Markdown 图片使用明确的相对路径：

```markdown
![图1 小问一的结果图](figures/fig_subproblem_1.png)
```

不要只把图片放在文件夹中而不在 Markdown 中引用。

### 4.4.1 论文语言风格与专业名词处理规范

在撰写各小问 Markdown 论文及最终总论文时，必须遵循以下语言风格与术语处理规则：

1. **专业名词突出显示（加粗标记）**：
   - 凡涉及统计学方法、优化算法、专业机理以及特定领域术语（如 `**主成分分析**`、`**中心对数比变换 (CLR)**`、`**多重共线性**`、`**双向逐步回归**`、`**非退化解**` 等），**必须统一使用加粗进行突出显示**。
   - **设计目的**：醒目标记专业术语，方便参赛队伍在最终通读和人工修改时，能够一眼定位并自主将其替换或补充为更接地气、通俗自然的表述。

2. **严禁自创简短生硬的短语**：
   - 坚决杜绝生搬硬凑的简短缩写、四字紧凑短语或生涩的合成词（例如禁止自造如“铅钡风度”、“聚类度差”、“残偏比”等生硬短语）。
   - 若某一现象或指标在现有学界无公认规范简称，**必须使用完整通顺的语句展开阐述**，严禁擅自造词。

3. **必要时允许并鼓励口语化表述**：
   - 论文在阐明数学模型时需要严谨，但在**建模思路引入、数学公式直观理解、现实背景说明以及最终结果的物理意义阐释**时，**允许且鼓励采用通俗、自然、口语化的中文**。
   - 拒绝通篇堆砌晦涩难懂的学术八股，力求用大白话把数学思维和逻辑讲透（例如：“通俗来讲，该约束保证了各组分配比例之和恰好为100%，不会产生物料凭空流失”）。

4. **严禁机械使用“小问”称谓，无明示时省略主语自然承接**：
   - 虽然解题工作流内部通常将复杂问题拆解为多个子任务（subproblem）进行模块化推进，但**如果实际比赛题目本身并未明确划分子小问，论文中严禁机械地写出“对于第一问的第一小问”、“在第一小问中”、“针对第二小问”等生硬用语**。
   - **正确处理方式**：直接省略小问主语，以具体研究任务或研究对象自然展开承接。例如写成：“首先对原始数据进行清洗与异常值检验……”、“进而建立多元回归模型求解各成分占比……”，小标题亦采用“数据预处理与特征筛选”、“成分关联度分析”等具体业务或方法命名，彻底抹去内部工程拆分的痕迹。

5. **模型假设与约定的命名与模板规范**：
   - 论文中模型假设部分**必须包含明确假设**；
   - 若模型中确有符号约定、物理常数预设或计算口径等额外约定事项，章节标题使用“**模型假设与约定**”；
   - **若没有约定事项，章节标题必须动态精简为“模型假设”**，严禁挂空“与约定”字样；
   - 每一条假设必须统一采用以“**假设……**”开头的标准句式模板（如 `假设1：假设检测数据真实可靠，未受取样过程中的二次化学污染；`），格式整齐规范。

6. **论文作图后必须紧跟深度论述，围绕图片得出结论**：
   - 严禁“放图不评”或仅写“如图X所示”就草草跳过分析；
   - 论文中嵌入图片后，正文紧接着**必须围绕该图片展开深入论述**；
   - 必须包含“**通过上述图片得出……结论**”、“**由图X可以看出，……**”、“**结合上述图片反映的变化规律，可以发现……**”等论述句式，剖析图片揭示的趋势、极值、分类特征，并明确其对后续建模求解的实体支撑作用。

### 4.5 小问阶段的检查门

一个小问只有在代码运行和论文撰写都完成后，才算完成：

- 方法和题目目标匹配；
- 数据清洗规则已经记录；
- 模型适用条件已经检查；
- 代码可以从头运行；
- 结果表格已经输出；
- 关键图片已经输出；
- 结果满足基本数学约束；
- 至少有一种验证或敏感性分析；
- Markdown 中的结论来自实际结果；
- 结论强度没有超过数据证据。

### 4.6 防止小问之间彼此割裂

逐小问推进可以提高效率，但必须同时维护大问题的总体逻辑。每个小问都要在 `subproblem_manifest.json` 中记录四类接口：

```text
上游输入：本小问使用前面哪些数据、变量、指标或结论
本问输出：会产生哪些表格、参数、分类、预测量或判断
下游用途：后续哪些小问会读取这些输出
兼容约束：单位、样本筛选、分组规则、符号、随机种子和版本
```

小问不是三个互不相干的独立题目，而是同一问题链中的模块。建议在每个大问题开始时先画出依赖关系：

```text
总体问题框架
  ├── 共享数据清洗与样本口径
  ├── 小问一：现象描述/因素识别
  │       └── 输出分类、分组或关键影响因素
  ├── 小问二：规律解释/参数估计
  │       └── 读取小问一的分组和变量定义
  └── 小问三：预测/优化/决策
          └── 读取前两问的参数、规律和适用性判断
```

每个小问可以单独写代码和Markdown，但不能单独重新定义数据口径。例如，前一问已经确定“普通风化”“严重风化”和“无风化”的分类规则，后一问就必须读取这份规则，而不能再次用另一套标签；前一问确定按玻璃类型分层，后一问也不能无说明地把两类样本混合。

### 4.7 小问之间的三次关联检查

至少进行三次跨小问检查：

1. **建模前检查**：确认小问一的输出是否确实是小问二的输入，确认各小问没有重复定义同一变量。
2. **单问完成检查**：小问代码运行后，检查输出是否覆盖下游需要的字段、参数、样本ID和单位；人工Excel表格只能用于展示，不能成为未经登记的模型输入。
3. **大问题冻结前检查**：统一重跑总流程，检查前一问的分组、后一问的模型、最终预测和论文叙述是否形成闭合链条。

如果后续小问发现前面小问的分类或数据处理不适用，应记录为“上游口径变更”，重新运行受影响的小问，不能只在最后论文中局部修改一句话。

## 5. 单个大问题的整合流程

当一个大问题的所有小问完成后，不直接拼接多个 Word 文档，而是对最终代码、最终结果和 Markdown 进行统一整合。

### 5.1 重新确定大问题的总体逻辑

检查各小问是否形成清晰链条，例如：

```text
小问一：描述现象或识别影响因素
   ↓
小问二：解释规律或估计参数
   ↓
小问三：进行预测、优化或决策
```

合并时统一：

- 符号；
- 数据口径；
- 样本筛选规则；
- 模型假设；
- 指标定义；
- 变量名称；
- 图表编号；
- 参考文献编号；
- 结论表述强度。

同时建立“小问输入—输出矩阵”，至少包含以下内容：

| 小问 | 读取的上游结果 | 本问核心输出 | 下游用途 |
|---|---|---|---|
| Qx-1 | 统一清洗数据 | 分类、描述性指标、关键分组 | Qx-2/Qx-3的分层或变量选择 |
| Qx-2 | 统一分组和变量定义 | 参数、规律、检验结果 | Qx-3的预测或优化输入 |
| Qx-3 | 前两问的最终口径和参数 | 预测、优化、决策结果 | 大问题结论和评价 |

若某小问没有上游输入，也要明确写出“独立分析”；若某个输出没有下游用途，则说明它是描述性或验证性结果，避免把它误当成后续模型参数。

### 5.2 生成大问题最终结果包

在整合论文之前，统一重新运行大问题的最终代码，生成唯一结果包。论文必须在这一步之后撰写或修订，不能先写最终数字再反向修改代码：

```text
problem_1/final/
├── final_analysis.py
├── tables/
├── figures/
├── metrics/
├── run_summary.json
├── solution_manifest.json
└── problem_1_final.md
```

最终结果包中必须包含：

- 所有小问所需的结果表；
- 所有论文所需的图片；
- 所有模型指标和验证结果；
- 统一运行时间、随机种子和环境信息；
- 输入文件和输出文件的哈希；
- 当前使用的模型版本。

### 5.2.1 区分“核心计算”与“人工排版表格”

为了减少最终代码的冗余，可以把输出分成三类，但不能把支撑论文结论的计算一并删掉：

| 输出类别 | 例子 | 最终代码要求 |
|---|---|---|
| 核心计算结果 | p值、效应量、CLR变换、FDR校正、模型参数、预测值、误差和敏感性指标 | 必须由代码重新计算并输出 |
| 机械汇总结果 | 原始数据计数、风化率交叉表、从结果CSV复制成的论文表格 | 可由Excel人工完成，但必须保存冻结的CSV/XLSX并登记来源 |
| 排版结果 | Word表格样式、合并单元格、字体、图题、页码 | 不放入分析代码，由内部排版工具完成 |

这里的“人工完成”只适用于计算规则简单、不会改变模型结论的机械汇总。例如，已知每类的无风化数和风化数后，在Excel中计算风化率并制作交叉表可以作为人工步骤；但产生这些计数的筛选规则、p值、Cramér’s V、优势比和置信区间仍应保留在核心分析链中。

最终交付时必须明确复现层级：

1. **代码全复现**：评委运行代码后可以重新得到论文使用的全部数字和图表。此时即使某张表在比赛中用Excel制作，也应在代码中保留等价的最小重建步骤，或由代码读取同包内的人工冻结表并进行哈希核验。
2. **结果包复现**：代码重新得到所有核心模型结果，人工表格作为同一结果包中的冻结CSV/XLSX交付，并在清单中写明“人工汇总”。这种方式可以精简代码，但不能表述为仅运行代码即可从原始数据恢复全部论文表格。

正式比赛建议采用第一种。删除的是“表格排版代码”和重复复制代码，而不是删除产生统计结论的计算。对于问题一，类型、纹饰和颜色的计数表可以用Excel排版，但Yates检验、固定边际蒙特卡洛p值、Cramér’s V和优势比仍由综合代码保留；CLR、BH-FDR、分层逆CLR、Bootstrap和留一验证全部保留。

### 5.2.2 综合代码的关联性要求

大问题的最终代码不能只是把几个小问脚本机械拼接在一起，而应当明确执行顺序和共享对象：

```text
统一加载与清洗
  ↓
小问一结果对象
  ↓
小问二读取统一样本口径并生成规律对象
  ↓
小问三读取前两问的分层、参数和适用性结果
  ↓
统一输出结果包
```

综合代码应避免把同一个数字分别写在多个小问脚本中。样本数、分组标签、参数、阈值和随机种子只在一个配置或数据对象中定义，其余模块读取该对象。这样既可以保留小问阶段的独立调试效率，也可以在最终阶段保证小问之间的逻辑一致。

### 5.3 图片登记制度

每一张论文图片必须有唯一编号和用途：

```text
Fig-P1-Q1：问题一第一小问分类比较图
Fig-P1-Q2：问题一第二小问规律分析图
Fig-P1-Q3：问题一第三小问预测结果图
```

建议在 `solution_manifest.json` 中记录：

```json
{
  "figures": [
    {
      "id": "Fig-P1-Q1",
      "file": "figures/fig_p1_q1.png",
      "purpose": "第一小问分类比较",
      "caption": "图1 不同类别结果比较"
    }
  ]
}
```

这样可以避免使用错误图片。例如，第一小问的分类风化率图不能被第三小问的预测均值图替代。

#### 5.3.0 表格与图片的“两阶段标号”生命周期

为兼顾“分小问独立开发调试的灵活性”与“整篇提交论文的严谨统一性”，工作流采用两阶段图表编号生命周期机制：

1. **阶段一：各小问起草与整合初期（分章节编号）**
   - 在各小问独立撰写、分析计算以及总论文初步合并阶段，表格和图片**统一先按照章节/问题进行编号**；
   - 命名格式：`图X-Y`、`表X-Y`（其中 X 为章节号/问题号，Y 为该章内部从 1 开始的顺序号）；
   - 示例：第一大题中的图表标为 `图1-1`、`图1-2`，`表1-1`、`表1-2`；第二大题中的图表标为 `图2-1`、`表2-1` 等；
   - 正文引用：正文紧扣该编号进行论述（如“通过上述图1-1可以得出……”、“如表1-2所示”）；
   - 优势：某个小问内部增删图表时，完全不影响其他小问的图表编号，便于并行编写与局部核查。

2. **阶段二：大问题装配与人工总体审核阶段（保持章节编号）**
   - 合并生成 master paper 初稿后，正文与图题保持章节级编号不变；
   - 参赛队员通读全篇，人工总体审核每个图表与其论述逻辑是否吻合、数字是否准确。

3. **阶段三：人工审核确认无误后的最终定稿（全局连续重编号）**
   - **触发条件**：人工总体审核完成、所有修改确认无误后；
   - **顺序重编号**：将全篇所有图片与表格按正文首次出现的先后顺序，全量重编号为全局连续顺序号：
     - 图片：`图1`、`图2`、`图3`、`图4`、`图5`……
     - 表格：`表1`、`表2`、`表3`、`表4`、`表5`……
   - **正文交叉引用全量同步映射替换**：
     - 记录旧编号到新编号的映射关系，正文中所有文字引用（如“由图1-1可以看出……”、“参见表2-1”）必须同步全量替换为对应新编号（“由图1可以看出……”、“参见表3”），严禁残留分章节旧编号。

#### 5.3.1 图表规划与出版级绘图门

最终结果冻结后、正式撰写小问论文前，必须对每个支撑结论执行一次“表格、图片、示意图或无需视觉”的选择。不得因为现有代码只输出了 CSV 就默认使用表格，也不得为了增加图片数量而制作没有证据作用的装饰图。

优先选择规则如下：

| 证据结构 | 优先形式 |
|---|---|
| 少量精确数值、参数、排名 | 三线表 |
| 趋势、分布、异常值、组间差异 | 折线图、箱线图、散点图或点图 |
| 相关、混淆、缺失、转移、双参数敏感性矩阵 | 热力图 |
| 预测、拟合或时间变化 | 观测—拟合图、预测曲线和不确定性带 |
| 分类性能 | 混淆矩阵，并配合适合类别不平衡情况的指标 |
| 参数扰动、稳健性或场景比较 | 敏感性曲线、区间图或小倍图 |
| 机制、依赖关系和算法步骤 | 流程图或结构示意图 |

每个正式图片计划至少记录：图号、所属小问、图片类型、源 CSV/JSON、支撑结论、目标章节、最终宽度、输出格式和渲染状态。对应计划保存在 `methods/Qx/qx_figure_table_plan.md`，并在最终 `solution_manifest.json` 中登记文件路径。

正式论文图必须由确定性代码从最终结果重新生成，不允许在图片编辑软件中手工修改数值、显著性标记或类别。推荐使用 Matplotlib；Seaborn、NetworkX 可作为同一 Python 绘图链的辅助库。ImageGen、Canva、Figma 等只可用于不承载数值证据的示意性素材，不得生成热力图、统计图或模型结果图。

正式图片输出约定：

```text
paper/figures/Qx/
├── fig_qx_name.pdf       # 优先嵌入论文的矢量版本
├── fig_qx_name.svg       # 可编辑矢量版本（兼容时）
└── fig_qx_name.png       # Word/预览兼容版本，通常600 dpi，最低300 dpi
```

相关热力图必须保持相同的变量顺序、色阶范围、中心值和颜色语义。相关或差异矩阵使用以零为中心的发散色阶；计数、概率和误差等单方向量使用顺序色阶。矩阵过密时只标注预先规定的重要单元格，完整数值保留在 CSV 或表格中。

生成完成后必须同时检查单张图片和嵌入论文后的最终页面，确认中文字体、负号、上下标、坐标单位、色条、图例、裁切和字号在最终放置尺寸下可读。仅运行绘图代码不视为通过图片检查。

#### 5.3.2 统一科研绘图颜色方案与生成规约

为确保全篇论文所有插图（无论由 Python 还是 MATLAB 绘制，包含相关性热力图、聚类图、折线图、柱状图、散点图等）在视觉上呈现出版级的高级感与色彩一致性，团队统一强制采用以下**科研绘图颜色方案（热力图·相关性·聚类分析）**：

1. **标准色表映射速查表 (HEX & RGB)**：
   | 梯度级别 | 语义说明 | 推荐十六进制 (HEX) | RGB 对应值 | 适用视觉场景 |
   | :--- | :--- | :--- | :--- | :--- |
   | **极高值** | 极大值/顶层聚类 | `#6A0624` | `(106, 6, 36)` | 热力图最高点、关键极值标记 |
   | **高值** | 强正相关/高指标 | `#B80824` | `(184, 8, 36)` | 强显著性、第二对比线 |
   | **偏高值** | 中强相关/偏高指标 | `#D71C2C` | `(215, 28, 44)` | 对比曲线、重点关注类 |
   | **中高值** | 弱正相关/适度偏高 | `#FEAB88` | `(254, 171, 136)` | 过渡区域、次要分类柱 |
   | **中等值** | 接近零/中性浅暖 | `#FDD2BC` | `(253, 210, 188)` | 浅粉暖色过渡、中度基线 |
   | **中性偏低** | 浅蓝过渡/中性偏弱 | `#C7E0ED` | `(199, 224, 237)` | 浅蓝冷色过渡、背景对比 |
   | **偏低值** | 弱负相关/适度偏低 | `#6FAFD2` | `(111, 175, 210)` | 次级蓝色系、置信区间填充 |
   | **低值** | 中强负相关/偏低指标 | `#327DB7` | `(50, 125, 183)` | 辅助分类曲线、湛蓝 |
   | **较低值** | 强负相关/低指标 | `#134B87` | `(19, 75, 135)` | 主方法/第一主曲线、深海蓝 |
   | **极低值** | 极负相关/极低指标 | `#053061` | `(5, 48, 97)` | 极夜暗蓝、最低点强调 |

2. **图表类型与色彩规则**：
   - **双极发散热力图 (Diverging Colormap)**：
     - 用于相关性矩阵（带数值）、层次聚类热力图、接触图与正负残差图；
     - 渐变路径：`#053061` (极暗蓝) $\rightarrow$ `#134B87` $\rightarrow$ `#327DB7` $\rightarrow$ `#6FAFD2` $\rightarrow$ `#C7E0ED` $\rightarrow$ `#FFFFFF` $\rightarrow$ `#FDD2BC` $\rightarrow$ `#FEAB88` $\rightarrow$ `#D71C2C` $\rightarrow$ `#B80824` $\rightarrow$ `#6A0624` (极深红)；
     - 相关系数矩阵必须以 `0.0` 为中心（白/浅色），`vmin=-1, vmax=1`。
   - **单向顺序色 (Sequential Colormap)**：
     - 蓝色系（非负特征、密度、概率、混淆矩阵）：`#C7E0ED` $\rightarrow$ `#6FAFD2` $\rightarrow$ `#327DB7` $\rightarrow$ `#134B87` $\rightarrow$ `#053061`；
     - 红色系（损失、风险、异常值）：`#FDD2BC` $\rightarrow$ `#FEAB88` $\rightarrow$ `#D71C2C` $\rightarrow$ `#B80824` $\rightarrow$ `#6A0624`。
   - **离散分类图表 (折线对比图、柱状图、散点图聚类)**：
     - 统一选用预设学术色板序列：主色1 `#134B87` (深海蓝)、主色2 `#D71C2C` (学术红)、主色3 `#327DB7` (湛蓝)、主色4 `#FEAB88` (珊瑚橙)、主色5 `#6A0624` (深酒红)、主色6 `#6FAFD2` (天青浅蓝)；
     - 基准线/对比参考线统一采用中性灰 `#767676` 虚线。

### 5.4 大问题 Markdown 合并与国赛标准模板规范

在最终结果包生成并核对无误后，将各小问 Markdown 内容整理到唯一的 master 论文文件中。
正文结构必须完全依照**全国大学生数学建模竞赛标准模板**（`plugins/math-modeling-workflow/assets/templates/national_contest_template.docx`，源自用户提供的官方国赛模板）的**十二大核心板块**进行组织：


### 5.5 参考文献真实性与权威性规范（GB/T 7714-2015）

在数学建模竞赛中，参考文献是评委考量论文严谨性、机理扎实度与学术诚信的关键窗口，**严禁任何形式的文献编造与劣质引用**：

1. **绝对真实，零编造（Zero Hallucination）**：
   - 严禁任何虚构作者、杜撰论文题目、伪造期刊卷期号或虚假 DOI 的行为；
   - 严禁将不同文献的作者、期刊和标题任意拼凑；
   - 所有引用的文献必须客观真实存在、信息确凿、可公开查证。

2. **权威性优先（Authoritative Sources First）**：
   - **经典教材与专著优先**：如姜启源《数学模型》、司守奎《数学建模算法与应用》、李航《统计学习方法》、周志华《机器学习》等，公信力最高；
   - **算法奠基性经典论文**：如 AHP、TOPSIS、随机森林、ARIMA 等经典理论的奠基文献；
   - **国家标准与官方年鉴**：涉及专业指标、环境或经济数据时，优先引用国家标准（GB/T）与国家统计局统计年鉴；
   - **核心学术期刊**：中文核心/CSCD，英文 SCI/EI/IEEE/ACM/Elsevier 等知名同行评议期刊；
   - **严禁劣质信源**：严禁引用未核实网络博客、论坛帖子（如 CSDN、知乎等）或自媒体文章作为参考文献。

3. **正文实引与文后清单 100% 对应（1-to-1 Mapping）**：
   - 凡文末列出的参考文献条目，正文必须有明确的方括号引用上标（如 `[1]`、`[2]`）；
   - 正文引用的位置必须与该文献支持的具体理论、公式推导或参数来源紧密相关，严禁文后挂空文献。

4. **严格遵循 GB/T 7714-2015 著录格式**：
   - **专著 [M]**：`[1] 姜启源, 谢金星, 叶俊. 数学模型[M]. 5版. 北京: 高等教育出版社, 2018: 120-135.`
   - **期刊 [J]**：`[2] 李晓东, 张伟. 基于改进 TOPSIS 法的综合评价模型研究[J]. 系统工程理论与实践, 2020, 40(5): 1234-1242.`
   - **标准 [S]**：`[3] 全国水环境容量测定技术委员会. 地下水质量标准: GB/T 14848-2017[S]. 北京: 中国标准出版社, 2017.`
   - **网络报告 [R/OL]**：`[4] 国家统计局. 中国统计年鉴-2023[R/OL]. (2023-10-15)[2024-09-01]. http://www.stats.gov.cn.`

## 6. Word 文档生成阶段

### 6.1 只在大问题完成后生成 Word

小问阶段不频繁生成 Word。完成一个大问题后，根据已经由最终结果包核对过的 Markdown 和结果文件整体生成 Word。

这样做的好处是：

- 减少排版等待时间；
- 避免重复调整分页；
- 避免多个 Word 文档合并时图片丢失；
- 统一标题、表格、公式和图注格式；
- 便于最终统一检查。

### 6.2 Word 生成脚本的职责

内部 Word 生成脚本应当：

- 读取最终 Markdown或结构化内容；
- 读取最终 CSV/JSON 结果；
- 检查图片路径；
- 显式插入图片；
- 插入图题和表题；
- 按模板统一排版；
- 输出 DOCX；
- 渲染 PDF和分页图片供检查。

内部脚本不应重新计算模型，也不应手工修改结果数字。

### 6.3 交付代码与内部工具分离

最终交付代码目录只放：

```text
deliverable/problem_1/
├── final_analysis.py
├── tables/
├── figures/
├── metrics/
├── run_summary.json
└── solution_manifest.json
```

不放：

- Word生成脚本；
- Markdown转Word脚本；
- 临时调试代码；
- 旧版本代码；
- 无关的缓存文件；
- 与题目无关的原始中间文件。

论文生成脚本保存在 `internal_tools/`，不进入最终代码交付目录。

### 6.4 人工表格的交付登记

如果某张表确实采用Excel人工汇总，必须在 `solution_manifest.json` 中登记，而不是让它成为无法解释的孤立文件：

```json
{
  "manual_outputs": [
    {
      "id": "Tbl-P1-Q1-01",
      "file": "tables/q1_1_weathering_rate_manual.csv",
      "source": "attachment1_standardized.csv",
      "rule": "按玻璃类型、纹饰、颜色分别统计无风化数、风化数、总数和风化率",
      "rebuildable_in_excel": true,
      "code_rebuild": "minimal_check_or_not_included",
      "sha256": ""
    }
  ]
}
```

人工汇总表不得手工改写核心模型结果，不得与代码输出重复使用不同的小数位或不同筛选口径。若评委要求“运行代码即得到全部结果”，则把 `code_rebuild` 改为 `included`，并保留最小重建代码。

## 7. 论文、代码和图片的一致性检查

### 7.1 输入一致性

- 论文和代码使用同一份清洗数据；
- 数据版本号一致；
- 变量名称和单位一致；
- 有效样本数一致；
- 删除记录和缺失值规则一致。

### 7.2 方法一致性

- 论文中的方法名称与代码一致；
- 论文中的公式与代码实现一致；
- 论文中的主模型、基线模型和备用模型状态一致；
- 论文中的检验方法与代码实现一致；
- 论文没有使用代码中未实现的方法。

### 7.3 数字一致性

至少检查以下数字：

- 样本总数；
- 分组样本数；
- 均值、比例和总和；
- p值；
- 置信区间；
- 预测点数量；
- 误差指标；
- 敏感性指标；
- 最终模型评价指标。

论文正文、表格、图片和 JSON 指标必须来自同一轮最终运行。

对于人工汇总表，核对链应写成：

```text
最终清洗数据/核心结果CSV
  → Excel人工汇总
  → 冻结CSV或XLSX
  → 哈希登记
  → Markdown/Word论文
```

不要把“人工完成”理解为可以随意修改数字。人工表格仍然必须有明确输入、公式、筛选条件、保留小数位和复核记录。

### 7.4 图片一致性

检查：

- 每一张预期图片都存在；
- 图片内容与对应小问一致；
- 图中数字与表格一致；
- 图题和图号正确；
- 图片清晰、居中、无裁切；
- 图片已实际嵌入 Word，而不是只存在于文件夹中。

Word 内部可检查：

```python
from docx import Document

doc = Document("final_paper.docx")
assert len(doc.inline_shapes) == expected_figure_count
```

## 8. 最终论文生成与审查

### 8.1 最终论文结构

整篇论文建议统一采用：

```text
摘要
关键词
一、问题重述
二、问题分析
三、模型假设
四、符号说明
五、数据预处理
六、问题一模型建立与求解
七、问题二模型建立与求解
八、问题三模型建立与求解
九、问题四模型建立与求解
十、模型评价与推广
参考文献
附录
```

具体编号根据题目实际情况调整，但全文应保持统一。

### 8.2 最终生成顺序

```text
冻结数据版本
  ↓
冻结方法版本
  ↓
统一运行全部最终代码
  ↓
生成最终表格、指标和图片
  ↓
生成最终Markdown（保持分章节图表编号：图1-1、表1-1）
  ↓
人工总体通读、审核与修改确认无误
  ↓
执行图表全局连续重编号（图1, 2, 3... 表1, 2, 3...）并同步全量替换正文引用
  ↓
转换为Word
  ↓
转换为PDF
  ↓
逐页检查
  ↓
重新检查关键数字
  ↓
制作提交压缩包
```

### 8.3 PDF逐页检查清单

每一页检查：

- 标题层级是否正确；
- 正文是否完整；
- 公式是否显示正常；
- 表格是否越界或断裂；
- 图片是否显示；
- 图题是否紧跟图片；
- 页码是否连续；
- 字体是否统一；
- 是否出现乱码、空白页或大面积异常空白；
- 是否残留教学说明、调试文字或临时标记。

## 9. 比赛期间的版本管理规则

### 9.1 版本命名

建议使用：

```text
draft_01       # 初步思路
round_01       # 第一次可运行版本
round_02       # 方法修正版
final          # 最终冻结版本
```

一旦进入 `final`，禁止再从旧版本复制表格或图片。

### 9.2 每次修改都记录原因

```text
修改时间：
修改文件：
修改内容：
修改原因：
是否影响数据：
是否影响模型：
是否需要重新生成图片：
是否需要重新生成论文：
复核人：
```

### 9.3 禁止事项

- 禁止直接修改原始数据；
- 禁止在论文中手工改数字而不修改结果文件；
- 禁止混用不同版本的代码、表格和图片；
- 禁止只检查 DOCX 文本而不检查 PDF 页面；
- 禁止把不同用途的图片当作同一张图；
- 禁止把备用模型结果写成主模型结果；
- 禁止把小样本下的描述性现象写成确定性因果结论；
- 禁止把论文生成脚本和临时文件混入最终分析代码交付目录。
