# 数学建模方法选择与建模核心原则

本规则适用于在数学建模工作流中进行题目解析、文献资料调研、方法筛选与模型构建的所有 Agent 与技能。

## 核心原则

### 1. 允许并提倡网络检索背景资料进行借鉴
- **背景资料调研**：
  - 在理解赛题与建立模型时，允许且提倡通过网络检索（Web Search）、文献数据库与权威行业报告，查找与题目相关的现实背景、物理/化学/生物机理、行业先验知识、标准常数以及同类经典赛题的建模思路；
  - 提取关键的业务约束、因果关系或评价维度作为先验参考，确保所建模型立足于客观规律与现实常理，避免脱离实际做纯粹的空洞数字游戏；
  - **规范要求**：借鉴背景思路，但不盲目抄袭或伪造无依据的文献；网络检索得出的重要参数或常识应在假设或符号表中明确注明其来源与依据。

### 2. 奥卡姆剃刀原则：简单模型优先（Simplicity First）
- **核心法则**：
  - **如果复杂的模型和简单的模型都能解决该问题，坚决优先选用简单的模型**。
- **为什么简单模型优先**：
  1. **高可解释性（Explainability）**：数学建模竞赛极其看重“机理说服力”，简单模型（如机理微分方程、多元线性/逻辑回归、经典线性/整数规划、经典统计检验等）具有清晰的数学推导和物理意义，远比难以解释的黑盒算法更容易获得评委青睐；
  2. **数值求解稳定（Numerical Stability）**：简单模型计算开销小、收敛性强，不易因参数调整而导致结果波动；
  3. **抗过拟合能力（Generalization & Robustness）**：竞赛数据往往样本量有限，复杂模型（如深度神经网络、过度参数化的复杂集成算法）极易发生严重过拟合与虚假高准确率；
  4. **时间与调试成本低**：使队伍有更多精力投入到数据清洗、特征构建、灵敏度分析与论文深度论述中。
- **选型判定规则**：
  - 只要简单经典模型能有效刻画核心规律并满足解题精度，必须将其作为**主选方法（Main Candidate）**；
  - 严禁为了“看起来高端”而无必要地上深度学习、复杂网络等过度复杂的模型；
  - 复杂模型仅在简单模型经理论证明或数据实测确实无法捕捉非线性特征、且存在明确触发条件时，方可作为候选对比或备用触发（Fallback）。

### 3. AI 全自动无人值守决策（Auto-Pilot Decision）
- **核心理念**：
  - 本工作流旨在实现 AI 端到端全自动运行，免除比赛期间人类队员的过程性思考与打卡负担，人类仅在最终版本合并渲染后进行通读终审；
- **自主决策规则**：
  - 在 G2.5 方法选型阶段，AI 必须依据“简单模型优先”和探针通过结果，自主选定最佳简单模型作为 `main_candidate`；
  - 决策流水账中直接记录 `decided_by: "autonomous_agent"` 并引用探针证据，立即放行 G2.5 进入代码编写；
  - 在 G4 结果评审阶段，计算无误且指标合理时，AI 自主记录 `result_verdict` 与 `package_signoff`（标记为 `decided_by: "autonomous_agent"`），立即放行 G4 进入论文撰写；
  - 严禁在无人干预时死锁挂起，必须依据预设科学准则自主推进全流程。

### 4. 强制落实“为什么选这个模型”的选型辩护证据 (Model Justification Requirement)
- **评委核心痛点**：评委最反感“凭空天降一个模型”。选型阶段不能只决定“用什么”，必须同时生成“为什么用它而淘汰其他候选模型”的论证材料，直接反哺论文撰写；
- **两套标准论证模式（二选一或结合）**：
  1. **路径 A：第一性原理机理推导法（机理/物理/动力学场景）**：
     - 从客观守恒律、物理/化学边界（如产率必须落在 $0\% \sim 100\%$）或微元速率方程出发，推导出闭式解；
     - 赋予参数明确物理含义（如起活半转化温度 $T_{50}$、活化能差 $\Delta E$），展现数理底蕴；
  2. **路径 B：候选模型打擂台对比法（统计/优化/机器学习场景）**：
     - 列出 2~3 个初学者常用的备选方案（如多项式拟合、纯黑盒随机森林、ANCOVA）；
     - 明确指出落选模型的致命硬伤（如多项式外推出现大于 100% 的荒谬溢出或虚假极值，黑盒算法在非平衡小样本下易过拟合且缺乏可解释性与 $P$ 值）；
     - 生成候选模型性能与适用性对比三线表（含拟合优度、物理自洽性、参数可解释性、淘汰/选用理由）。
